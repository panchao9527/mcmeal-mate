# 麦麦搭子 McMealMate Skill

**在聊天里把大家的饭买齐：选餐、核价、确认下单、查取餐码、算分账。**

> 我们3个人，人民广场附近外带，100元以内。小王主食不要牛肉，小李饮料无糖，我要汉堡，再一起分一份薯条。帮我们买齐，每人多少钱也算清楚。

麦麦搭子把几个人零散的要求合成一份购买清单，比较当前可买的餐品、套餐和已持有的优惠券。你确认清单后，AI客户端创建一笔待支付订单；你在官方页面付款，再让它查询取餐信息、按实际金额分账。

**v0.4 的主入口是 Skill 对话。** 复用AI客户端的麦当劳MCP。附带Python助手离线管理需求、核价、购买确认和订单状态，不读取Token、不联网；无需启动网站。当前支持1至8人到店自取。

## 三步使用

1. **安装技能包**：[下载 mcmeal-mate-skill.zip](https://github.com/panchao9527/mcmeal-mate/raw/refs/heads/main/dist/mcmeal-mate-skill.zip)。WorkBuddy 中按“技能 → 添加技能 → 上传技能”导入；其他客户端见[安装教程](docs/INSTALL.md)。客户端需支持本地 Skill、MCP 与 Python 3.10+ 执行。
2. **连接一次官方 MCP**：在客户端配置 [麦当劳官方 MCP](https://open.mcd.cn/mcp)。已有连接就直接复用；Token只放客户端设置，技能不会再要求把它写入脚本。
3. **直接说需求**：输入上面的例子。AI补齐必要信息、确定门店并核价。选方案后看清购买清单，回复“确认下单”；在返回的官方页面付款，再说“付好了，查取餐码”。

后续可以直接说：

- “预算改成80元，其他要求不变。”
- “小李不参加了，重新安排。”
- “就买省钱方案。”
- “付好了，查一下取餐码。”
- “把实际分账发给我，我复制到群里。”
- “按上次再点，这次小李不参加。”

第一次还没有账号？先说 **“使用麦麦搭子，做一次无账号买餐演练”**。它会生成从选餐到模拟取餐、分账的完整演练；餐品、金额、订单、链接和取餐码均为虚构，不能用于实际购买。

## 你会得到什么

- **每个人都有个人餐**：1至8人，支持主食类别、饮料、薯条等硬性要求，以及口味软偏好。
- **两套可比较的方案**：说明价格、预算余额与放弃的软偏好，不宣称全菜单最低价。
- **当前官方整单核价**：候选先试算，最终完整商品清单再核价，附门店和报价时间。
- **从清单走到订单**：展示一份具体清单，确认后重新核价，再由宿主创建待支付订单；价格变了需重新确认。
- **付款后查取餐**：你自己付款，AI查询官方状态；只有已核实支付才展示取餐信息。
- **算到分的分账**：共享小食只分给食用成员，整单价差按原金额比例分摊。
- **保留上次需求**：复购时重新检查当前供应和价格，避免沿用过期套餐或旧预约时间。
- **可以带走的结果**：聊天表格与群分享文案，包含每人餐品、金额、共享品名和数量。
- **清楚的冲突反馈**：预算不足、当前不售卖、属性未知或旧报价不匹配时说明问题，保留用户的硬性要求。

## Skill 怎样工作

```text
用户自然语言
  → AI客户端调用已连接的麦当劳MCP
  → 查询门店、当前菜单、详情、营养和候选报价
  → 离线助手计算两种配餐方案
  → AI客户端按导出的准确参数调用官方整单核价
  → 展示购买清单 → 用户确认 → 再核价
  → AI客户端执行一次create-order → 返回官方支付入口
  → 用户付款 → query-order核实 → 取餐信息与实际分账
```

商品编码、套餐轮数、饮料替换均取自本次工具返回。Skill 主流程没有固定商品编码清单，能够处理新候选和不同轮数的套餐；这不代表自动遍历全部菜单。

候选、整单参数和报价通过方案指纹关联，修改预算、人数、门店或餐品后需重新核价。过期、失败、金额格式错误或错配的报价会被拒绝。指纹是文件一致性检查，不是官方数字签名。

下单导出是单次使用；超时或结果不明时先查询订单，避免重复创建。确认文字必须来自当前用户看到清单后的真实回复。脚本的一致性检查不能代替宿主等待用户，也不是官方签名验证。

有用户指定能量上限时参考官方标准份量；无法匹配的营养保留未知。肉类和口味分类不能保证过敏、交叉接触或严格配料安全，需要另向官方核实。领券、购卡和积分消费需要另外的明确请求。
