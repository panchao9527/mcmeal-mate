# 参赛演示：多人点餐，一次买齐

## 真实连接演示

前提：目标客户端已导入技能包、能执行Python，且已连接用户自己的麦当劳MCP。演示前验证真实工具可用，切勿把模拟对话当作已执行记录。

用户：“使用麦麦搭子，上海人民广场附近，3人到店取餐，预算100元。小王主食不要牛肉，小李饮料无糖，我想吃主食和饮料。”

AI：读取Skill，查询营业门店，让用户选择；查当前菜单和详情、按实际供给构建候选，调用候选试算；离线计算两种方案，导出最终商品参数，再由宿主MCP执行整单核价。

展示：聊天中的两种方案对比、每人餐品与金额、门店和核价时间，以及共享小食明细和可复制群清单。

用户：“预算改成80元，其他不变。”

AI：保留成员和偏好，重新规划、重新核价；不能给旧回执换上新指纹。若预算不够，解释候选范围内的冲突并给出调整选项。

用户：“就买省钱方案，外带，不要餐具。”

AI：更新上下文并重新核价，展示门店、每人实际餐品和份数、共享薯条、饮料替换和特制、取餐方式、预约时间、餐具与总价。

用户：“确认下单。”

AI：再核价。金额或取餐说明变了就重新确认；未变时创建一笔待支付订单。保存真实回执后给官方支付入口，用户自己付款。演示拍摄只有用户本次确实要购买时才能走这一步，不为了演示创建真实订单。

用户：“付好了，查取餐码。把每人实际多少钱算一下。”

AI：查询一次官方订单状态，核实已支付后展示当前取餐信息；按订单实际金额生成可复制群清单。群文案不包含支付链接或取餐密码。

用户下次：“按上次再点，这次小李不参加。”

AI：读取旧需求，保留其他条件，检查当前供应并重新核价；重新展示购买清单，等待本次确认，不直接重复旧订单。

## 无账号演示

用户：“我还没连接麦当劳MCP，先让我试试。”

AI：按Skill执行doctor和demo，无需网页或Token。展示两种虚构方案，并打开生成的`buying-transcript.md`：选省钱方案→确认→模拟待支付→模拟支付查询→演示分账。模拟取餐码不可用于取餐，零网络、零真实订单。

离线演练可复现，不能替代真实宿主、下单或付款验收。不要将模拟对话拍成真实订单成功证明。
